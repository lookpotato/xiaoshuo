# 统一小说系统的作者内核（原 V2）

这里不再是一套独立运行的小说生成系统。工作台、命令行生成、自动修复、人物线、配图、归档、发布和 Git 都统一由 `xiaoshuo.py` → `xiaoshuo_on_demand.py` 这一条生产流程负责；本目录保留作者档案、受控上下文组件和相关验证代码，供统一流程与副作者反馈系统复用。

`novel_v2.py` 仅作为旧命令兼容入口：`run` 转交统一生产流程本地生成一章，`prepare` 预览同一流程，`validate` 转交管理器检查。它不会再启动第二套章节生成器，也不会创建独立写作状态。

## 保留下来的作者能力

- 作者模块是最高创作来源；系统不再默认模型自身就是作者。
- 作者档案保存稳定创作方法、读者承诺、语言原则和已确认的长期经验。
- 每本书仍通过 `system.json` 绑定作者，但实际写章只由统一生产流程执行。
- 副作者确认的共性经验可以提升到作者档案，成为以后所有绑定作品的长期能力。
- 单本书经验保存在作品目录中，只影响该书，避免污染作者的通用能力。

## 实际执行链

1. 工作台或命令行调用 `xiaoshuo.py`。
2. `xiaoshuo_on_demand.py` 读取作品资料、绑定作者档案、单书反馈经验和文风指南，完成写章与自动返修。
3. 同一流程继续完成人物线检查、配图、归档、发布和 Git 同步；具体是否启用由本次运行参数决定。
4. 副作者的读者反馈进入待确认学习项，确认后提升到单书经验或作者长期经验，供下一章继续使用。

本目录中的导演、陌生读者和上下文装配代码属于可复用的作者内核与历史实验实现，不再拥有独立生产入口，也不单独更新章节状态。

## 兼容命令

```powershell
python novel_v2.py validate --book cosmic-404
python novel_v2.py prepare --book cosmic-404 --signal new_object --signal dialogue
python novel_v2.py run --book cosmic-404 --signal new_object --signal dialogue
```

`prepare` 现在只预览工作台使用的统一生产流程，不再创建 `.novel_runs_v2/` 写作包。

`run` 会转交统一生产流程，以本地归档模式生成一章，不发布番茄也不执行 Git。自动返修上限、能力装配和门禁全部以统一生产配置为准。

作者配置暂时保留在 `novel_engine_v2/authors/`，每本小说通过 `system.json` 绑定一名作者。虽然目录名沿用 V2，但绑定作者档案已经由当前生产写章、自动返修和副作者反馈共同读取，不再只服务另一套生成器。作者不是“文风词表”，而是稳定创作方法、读者承诺、语言原则和经副作者确认的长期经验。

《道友你这天命与我有缘》旧版继续使用 `free-sky`；新书 `free-sky-rewrite` 使用独立目录 `道友你这天命与我有缘_重写版/`，从第1章重新开始。原目录及56章旧稿不覆盖，只作为研究样本；重写蓝图仅供新书导演规划，不会整份进入作者写稿上下文。新书未绑定番茄书号，默认只在本地写作。
