# 新时代自动小说系统（V2）

V2 是独立于旧提示词链的新写作内核。旧系统不删除，只作为作品资料、失败样本和发布适配来源。

## 核心区别

- 作者模块是最高创作来源；系统不再默认模型自身就是作者。
- 导演、作者、陌生读者、归档分别使用独立上下文。
- 写稿阶段最多装配两个模块，审稿阶段最多三个模块。
- 旧版 `automation_prompt.md`、大型经验文件和验收报告不会进入写稿上下文。
- 审稿只区分阻塞问题和非阻塞提醒，措辞偏好不能阻止归档。

## 主流程

1. 导演读取作品方向、状态和最近正文，生成一份本章合同和不超过 6000 字的受控作者上下文。
2. 作者只读取作者配置、本章合同、受控上下文和最近正文，写候选稿。
3. 陌生读者只读候选稿，检查正文能否独立成立及是否具有作品唯一性。
4. 通过后由归档阶段更新项目文件；发布、配图和 Git 由独立适配器处理。

## 使用

```powershell
python novel_v2.py validate --book cosmic-404
python novel_v2.py prepare --book cosmic-404 --signal new_object --signal dialogue
python novel_v2.py run --book cosmic-404 --signal new_object --signal dialogue
```

`prepare` 会在 `.novel_runs_v2/<作品>/<章节>-<时间>/` 生成四个阶段的提示文件和上下文清单。它不会写正文、修改章节状态或发布。

`run` 会用互相隔离的 Codex 临时上下文依次执行导演、作者和陌生读者阶段。读者只把理解断裂列为阻塞问题；最多返修两次，通过后由程序复制候选稿、保存 `continuity_v2/NNNN.json` 并推进章节状态。V2 暂不自动发布和配图，这两项留给独立适配器，不能重新混入创作提示。

作者配置位于 `novel_engine_v2/authors/owner.json`。只有用户明确认可的偏好才能进入作者配置；暂未校准的部分保留为未知，不能由系统猜测。
