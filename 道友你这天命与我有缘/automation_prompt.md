# 《道友你这天命与我有缘》自动创作约束

每次只处理 `chapter_state.json` 指定的下一章，并严格串行：读取设定与最近三章 → 写章纲 → 写作 → 质量校验 → 修订 → 本地归档 → 更新状态与连续性账本 → 写日志 → Git 提交与推送。

## 必读顺序

1. 根目录 `AGENTS.md`
2. `fanqie-auto-novel` 技能及其要求的引用文件
3. 共享层只读取根目录 `shared/quality_scorecard.md`、`shared/image_workflow.md`、`shared/reader_gate.md`，用于底层质量门禁；不得从共享写作手册或跨书经验日志继承创作风格
4. 本书 `novel_config.md`、`outline.md`、`characters.md`、`world.md`、`destiny_children.md`、`style_guide.md`
5. `publish_config.md`、`chapter_state.json`、`continuity_ledger.md`
6. `chapters/` 中最近三章与当前排期文件

## 当前执行模式

- 本书已绑定独立番茄书号，`mode=write_then_upload`、`submit_publish=true`。
- 默认未来档期为每日 18:30、20:30；每章仅在章节管理页显示待发布、审核中或已发布后才可记为成功。
- 必须核对作品名与独立 book_id；不得借用其他作品地址。遇登录验证、验证码、风控、政策警告或陌生确认框立即停止。

## 章节硬门槛

- 第29章起先定主情绪、一个人人看得懂的瓜、两个轻松/痛快互动节拍和一个评论区按钮，再规划规则与行动。情绪价值高于推理解密；若主要阅读体验仍是查碑规、验官印或复盘证据，即使逻辑正确也只能保留草稿重写。
- 写本章前必须按实际运行日期联网搜索最近7天的公开热梗与评论表达，至少交叉查看2个带时间戳来源；不足时才放宽到30天，禁止拿年度盘点、去年热词或无日期合集冒充实时。把扫描时间、来源、候选、选中结构、仙侠化改写和使用场景写入本书当日运行日志的 `meme_scan`；联网失败时使用本书原生笑料，不用旧梗顶替。
- 每章必须设置1个评论共创接口，在起外号、判责站队、预测天条回旋镖、续写村口传闻/陆遥歪理或替招式战利品命名中轮换；正文要先给足事实，再留下至少两种合理接法，不能由旁白自己把梗说完。每章最多1次明确邀请评论，只邀请围绕剧情玩梗，不索要支持、点赞、打赏或催更。写章前若番茄页可正常读取上一章真实评论，抽样查看最新与高赞评论并把高频梗匿名记录到运行日志；适合时让其成为村口外号、榜文边注或阿绒的新损话并产生小后果。读不到就不回收，严禁伪造“读者都说”。允许出现“读者老爷、评论区”，但仍禁止暴露AI与生产流程。
- 本书当日运行日志必须记录 `comment_seed`（接口类型、正文铺垫、开放问题、至少两种可能接法）与 `comment_harvest`（评论是否可读、抽样范围、匿名高频梗、是否在正文回收）；评论不可读时如实记空，不得脑补。
- 复杂谜题允许多写几章，但每章只处理一个核心判断，并独立兑现一次笑、爽、暖、燃或心疼；普通人必须参与传话、站队、起外号或承担选择，不能只充当震惊背景。
- 正文目标 1900—2200 字，以约 2000 字为中心，常规硬上限 2400 字；预计超长就在阶段胜负处拆章，原本约5000字的剧情改成2—3章，不删打斗、因果和人物反应。
- 开头 300 字内出现目标、异常或危险后果。
- 本章至少推进情节、关系、能力、真相中的两项。
- 新能力必须符合青羽“看路而非代打”的限制。
- 使用或夺取命痕前必须核对 `destiny_children.md`：只取最小残片，不继承修为；记录来源、槽位、试用次数、反噬、命债和消化阶段。
- 新命痕不得提高当前境界、灵力总量或肉身上限；跨一大境界获胜必须至少依赖两项外部条件，高两境只允许逃脱或完成局部目标。
- 结尾钩子必须由本章结果自然产生。
- 陆遥每章至少有一次主动选择，并表现“嘴欠、装怂、抓规则漏洞”中的至少一项；不得写成只会讲大道理的正经主角。
- 敌人施压后，本章至少兑现回嘴、占便宜或埋坑之一；完整回击最迟 3 章内发生，且必须带来实际收益。
- 钩子在下一章前 30% 必须得到回应，不能用新意外无限延期。
- 不得泄露 AI、提示词、自动化、账号信息或其他书籍发布数据。
- 新道具首次出现时先直说基础用途并在同章尽快触发效果；若完整效果延至下一章，本章须出现征兆。隔章再用前用一句情境化短句回顾用途或限制，悬念只保留来源、上限和隐藏代价。
- 每4—6章至少新增、夺取、修好或升级一件可持续实战装备，优先轮换飞剑、小炉、飞行翼、护身法器、阵旗、甲片和储物器；连续两件不得都是解谜/验印/过关道具。新装备2章内实战验货，后续至少复用两次并体现损耗或组合。低潮最多连续2章，败退也必须拿到反攻筹码。
- 读取本书 `images/catalog.json`；每章只为最需要视觉解释的一个新实体通过图片专用 Chrome 调用网页 GPT 配图，同名实体沿用旧图。同章其他新实体必须用正文白话解释。网页成图下载后直接采用，禁止调用 Codex `view_image` 回看或按主观画面重生；只校验文件头、哈希、像素画幅、目录、正文引用与番茄上传回显。文件未落盘、损坏、画幅错误或目录校验失败时只保留草稿。
- 从第 17 章起执行 `shared/reader_gate.md`：大纲关键句不得直接充当前提，正文补齐“承接→问题→依据→判断→行动→结果”；完稿后停止读取大纲和设定，只读正文完成六题，每题引用原句并清零未解释名词，保存 `reader_checks/NNNN.json`。缺失、哈希不符或未通过不得归档。
