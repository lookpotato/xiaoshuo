# V3 作者房间生成链

V3 是一次独立的新生成链，不是 V2 的规则扩充，也不覆盖旧作品正文。

## 核心变化

旧流程把大量正确经验放在“写作前要求”和“写作后检查”里，容易生成符合规则但没有生活的正文。V3 把中心换成作者房间：先让人物带着自己的生活、关系债、现实目标和未说出口的顾虑进入场景，再让办事、帮忙、推诿、误会和冲突推动故事。

V3 不要求正文填人物属性表，也不规定中国人必须使用某种句式。它只在生成前提供有限的生活判断，在生成后做一次深层编辑和中国读者读感检查。

## 阶段

1. `director`：读取作品资料和配置的最近章节，生成经校验的章节合同。旧楼作品另规划故事日、23:47 与最高楼层。
2. `characters`：逐人生成私线和按时间排序的交织表。
3. `author_room`：依据合同、私线和作品资料形成这一章的生活判断。
4. `scene_seed`：根据规划写数百字真实场景粗稿，先确定人物说话和叙述的声音。
5. `draft`：只读取场景粗稿与程序生成的简短事实边界，在新鲜上下文中扩写完整正文。
6. `deep_edit`：只参考粗稿、候选稿和事实边界，修正破坏现场感的地方；程序校验后一次性替换。
7. `reader`：由陌生中国读者检查现场可信度、关系和对白，不补设定。
8. `continuity`：按最终正文回写每个人物的状态并审查承诺、时间和空间。旧楼作品还须给出逐夜增层证据；缺失或冲突会阻止归档。

读者检查若发现阻塞问题，系统会保存每轮审稿，并用最新阻塞评语自动返修、重新调用独立读者复检，最多返修三次。通过后才归档；三次后仍未通过时，报错会列出剩余阻塞句子并保留运行包，不推进章节状态。可用 `python novel_v3.py resume --book <作品ID> --run-dir <运行包目录>` 从该运行包继续返修。

归档还要求章节合同、人物私线、交织表、全体状态回写和连续性审查齐全。旧楼作品从 `timeline_state.json` 的上一章终点推算故事日与楼层，并核对章节合同、最终正文引用和新增楼层事件；通过后才推进该状态。旧版运行包不能跳过这些阶段续归档，需重新准备章节。

这几个阶段是上下文隔离，不是正文结构。正文仍然可以自由发现节奏、顺序和对白。

## 参考文本原则

好小说用于观察人物如何生活、关系如何变化、信息如何从行动里露出；失败小说用于记录翻译腔、功能化人物、过度解释和关系失真。只保存研究结论和自写场景经验，不复制受版权保护的原文，不让某一个作者变成模仿模板。

统一工作台可在系统设置中选择 V2 或 V3；当前默认 V3。V3 的读者检查通过后归档本地章节，暂不上传平台。
