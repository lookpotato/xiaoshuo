# 番茄章节发布界面操作规程

本文件记录《404修理站》当前番茄作家后台的已知页面结构。只有页面作品名与
`publish_config.md` 中的 `book_id` 完全匹配时才能执行。

## 章节编辑页

1. 进入目标作品的“篇章/新建章节”页面。
2. 章节编号区域由固定文字“第”和“章”包围；只在中间的数字输入框填写纯数字
   章节号，不得把“第”“章”重复填入。
3. 点击占位文字为“请输入标题”的标题输入框后填写标题。标题必须超过 5 个汉字，
   自动化写作时按至少 6 个汉字校验。
4. 正文编辑区可能显示“开新书没思路？试试AI开书灵感，帮你生成大纲”。
   不得点击该提示；应点击它前方的正文空白区域，确认光标进入文本输入状态后，
   粘贴纯正文。
5. 章节号、标题、正文必须串行输入，不得在同一页面并行填充，避免焦点错位导致正文未进入编辑器。
6. 正文不得包含 Markdown 章标题、分隔线、Metadata、写作说明或自动化信息。
7. 粘贴正文后必须等待平台字数刷新，并同时核对正文首段、末段、平台显示字数和本地目标字数。
   若正文为空、仍显示提示词、首尾不匹配、平台字数为 0 或明显偏离本地章节字数，不得点击“下一步”。
   应重新点击正文空白输入区并重贴一次；重试后仍不正确，记录 `failed_retryable` 并停止。
8. 填写后核对章节号、标题、正文首尾、平台显示字数和目标作品名，再点击右上角
   “下一步”。

## 已知确认流程

以下弹窗属于用户已经确认的固定发布流程：

1. 出现“检测到你还有错别字未修改，是否确定提交？”时，先确认当前目标仍是
   《404修理站》，然后点击“提交”。
2. 若平台显示“请选择内容检测方式”，且选项包含“仅基础检测”，选择
   “仅基础检测”。若按钮文案显示为“基础检测”，确认语义一致后选择该项。
   不选择“全面检测”。
3. 进入“发布设置”后，在“是否使用AI”中选择“是”。
4. 打开“定时发布”右侧开关，点击日期/时间控件，在日期选择器中选择排期日期。
5. 常规排期首章选择中午 12:00；同日第二章选择平台允许的最近可用时段。若平台
   允许同日同一时刻多章排期，则两章均可按用户要求设为 12:00。
6. 用户临时要求某日加更时，只增加指定日期的章节，不改变之后每日 2 章的常规排期。
7. 核对章节号、日期、时间、“是否使用AI=是”和定时开关后，点击“确认发布”。
8. 对于 `submit_publish: true` 的正式书，停在“存草稿”或草稿箱列表不算完成。
   草稿只用于页面异常后的续传中间态；必须继续走到“待发布”“审核中”或“已发布”的
   可见状态，才能记录本章发布成功。

## 成功与停止条件

- 只有看到明确的发布成功、已提交审核，或章节列表中目标章节显示为“待发布”“审核中”
  “已发布”等非草稿状态，才能记录成功。
- 若目标章节已保存到番茄草稿箱但未完成确认发布，记录 `publish_pending`，
  下次必须从该草稿继续提交，不得把草稿状态报成完成。
- 登录失效、验证码、二维码、手机验证、账号风控、作品名或 `book_id` 不匹配、
  内容审核拦截、固定流程以外的新警告或确认框，必须停止并记录
  `blocked_manual`。
- 网络加载失败、控件暂时不存在或页面超时，记录 `failed_retryable`，不得换用
  其他作品链接。

## 打赏加更的章节管理入口

1. 加更只调整已进入“待发布”“审核中”或未来发布队列的既有章节，不新建章节、
   不重写标题和正文。
2. 章节管理列表每页最多 15 条，新增章节出现在第 1 页并把旧记录逐步挤到后页；
   因此禁止用固定页码或固定行号定位。
3. 从第 1 页开始，以“第N章 + 完整标题”匹配目标行；本页不存在时点击可用的
   下一页，直到找到目标或下一页禁用。分页过程中章节身份匹配必须始终唯一。
4. 目标行最右侧操作列的编辑入口当前由 `span` 承载。点击后必须回读编辑页中的
   章节号和标题；任一不符都停止，不能依靠页面位置猜测。
5. 身份核对无误后，不修改正文，按既有固定发布流程进入下一步并更改日期、时间；
   日期和时间都通过可见选择器点击，最终回读四项设置后只确认一次。
6. 返回章节管理页时仍需跨分页找到同一章节并读取状态。平台确认成功后，立即把
   新排期和原排期历史同步到本地批量排期文件、章节状态与当日日志。

## 页面变化的自我更新

- 每次发布都对照本文件记录实际页面标题、控件文案、选择状态、成功信号与最终 URL。
- 文档未覆盖的新界面若仅是已授权动作的同义改版，必须先通过页面上下文确认语义，
  操作成功后把新文案、可靠定位方法和验证结果补入本文件及当日日志。
- 新政策确认、内容风险告警、身份验证、验证码、付费、删除、覆盖章节或其他不可逆
  动作不属于可自动学习范围；必须停止并报告，由用户首次确认后才能写入固定流程。
- 页面观察只能强化操作规程，不得把 Cookie、登录令牌、验证码或其他账号秘密写入
  文件或 Git。

## 浏览器控制中断的诊断与恢复

1. 浏览器控制日志若出现 `ab.chatgpt.com` 或 `Statsig` 请求超时，而番茄页面仍能读取，
   视为控制层遥测失败，不直接判定番茄提交失败。
2. 每次控制调用只执行一个有副作用的动作。点击后必须另起一次只读检查，禁止把
   “下一步→提交→基础检测→发布设置→确认发布”打包进同一个长调用。
3. 单个页面动作至少预留 60 秒。若调用超时或控制连接重置，最后动作的结果一律记为
   “未知”，不得立即重放。
4. 结果未知时，复用原浏览器会话并重新取得现有标签页；依次读取当前 URL、可见弹窗、
   章节号与章节列表状态，再从已确认的步骤继续。
5. 番茄的日期和时间是受控组件。必须点击可见日历日期和时间列表选项，不得只向
   输入框写值；直接填值可能显示片刻后回退为平台默认值。
6. 点击“确认发布”前必须回读：章节号、标题、日期、时间、AI=是、定时开关=true。
7. 点击“确认发布”后若连接中断，只允许去章节管理列表做一次只读核对。目标章节
   显示待发布、审核中或已发布才算成功；否则保留 `publish_pending` 或
   `failed_retryable`，不重复确认。

## 已验证的端到端成功流程

以下细节由第19章和第20章在 2026-07-27 至 2026-07-28 的实际发布验证，适用于
相同页面结构。页面发生变化时仍需先读取当前可见状态，不能盲点固定坐标。

### 一、恢复或打开目标草稿

1. 优先从批量排期文件和当日日志取得章节号、草稿 URL、计划日期与时间。
2. 已有草稿时打开该草稿编辑 URL；不得访问“新建章节”重新创建同章。
3. 重新打开后若页面显示章节号、标题和完整正文，但没有“发布设置”弹窗，说明
   上次设置只是临时页面状态，尚未最终提交。此时从“下一步”重新执行发布检查。
4. 进入下一步前读取作品名、章节号、标题、正文首段、末段和平台字数。任一项不符
   都停止，不靠后续页面纠正。

### 二、固定发布弹窗

1. 唯一定位右上角“下一步”并点击一次；动作结束后另起只读检查。
2. 若出现“发布提示：检测到你还有错别字未修改”，唯一定位按钮“提交”并点击一次。
3. 只读确认出现“请选择内容检测方式”后，唯一定位“仅基础检测”并点击一次。
4. 只读确认进入“发布设置”，且章节摘要仍是目标章节。
5. “是否使用AI”的底层 radio 可能不可直接勾选；应点击发布设置弹窗内可见文字
   “是”，再回读第一个 radio 的 `checked=true`。
6. 唯一定位发布设置弹窗内的 `switch` 并点击；回读
   `aria-checked=true`，确认定时发布已打开。

### 三、日期与时间

1. 打开日期输入框后，通过可见日历选择日期。月末页面会同时显示下月日期；
   必须结合当前年月、是否属于本月的单元格样式和目标日唯一定位，不能只按数字点击。
2. 时间输入框默认为平台当前建议时间时，若该时间符合排期，可以保留；若需修改，
   必须通过可见时间列表选择并确认。
3. 不得直接对日期或时间输入框执行 `fill`。番茄使用受控组件，瞬时 DOM 值可能
   随后回退。
4. 点击最终确认前一次性只读回查：
   - 日期输入值等于计划日期；
   - 时间输入值等于计划时间；
   - AI 的“是”单选为 checked；
   - 定时发布 switch 的 `aria-checked` 为 true。

### 四、确认与权威成功信号

1. 四项回查全部通过后，唯一定位“确认发布”并只点击一次。
2. 不以点击调用返回成功作为发布成功；必须等待或只读检查页面是否返回章节管理 URL。
3. 在章节管理表格中按“第N章 + 完整标题”唯一匹配目标行。若匹配数量不是 1，停止核对。
4. 从目标行同时读取状态和发布时间：
   - `审核中`：已经进入发布流程，通过审核后会变为待发布；
   - `待发布`：已经进入定时队列；
   - `已发布`：发布完成。
5. 以上三种状态都可作为本章上传完成信号。草稿、空行、仅看到页面其他章节的
   “待发布”，均不算目标章成功。
6. 成功后立即更新 `chapter_state.json`、对应 `batch_schedule_*.json` 和运行日志。
   批量任务只有完成本章回写后才能处理下一章。
